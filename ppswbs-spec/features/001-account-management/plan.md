# Implementation Plan: Member Profile
**Date**: 2026-10-19 | **Spec**: [spec.md](spec.md)
**Approval**: Original feature plan plus the user's explicit instruction to apply “Sửa spec 003: xác thực về trang chủ, policy không chặn hồ sơ”. This update changes the documented journey/access rules only; it does not authorize production implementation in this task.
## Technical Context
Java 21, Spring Boot 3.4.1, Thymeleaf, Spring Security, JPA, Flyway, Firebase Admin SDK 9.11.0 and MySQL 8.4. Existing JUnit/Spring Boot Test/MockMvc; H2 is supplemental only. Firebase Auth Emulator and disposable MySQL are selected for integration verification. No new production framework.
## Constitution Check
Closed members module owns persistence, use cases, DTOs, controllers and profile identity adapter. Separate profile SecurityFilterChains in configuration consume a members facade exposing only authentication boundary primitives. No entities/controllers/infrastructure exported. No raw SQL in application code. Firebase owns tokens/cookies/passwords. CSRF and server forms preserve the no-JS profile baseline. No architecture exceptions added.
## Design
- Dedicated profile API and web security chains ordered before existing fallback; do not alter security behavior of preexisting routes. Prevent profile auth filters from auto-registering as global servlet filters.
- Firebase identity adapter verifies ID tokens/cookies with checkRevoked=true and issues eight-hour cookies; safe identity record contains UID, email, verified flag and auth_time only. No client roles.
- Web public auth/session bootstrap routes use CSRF; protected profile/logout use cookie identity. Cookie name __Host-mland_profile. Invalid/expired cookies redirect to the fixed sign-in page, not user-controlled URLs. Follow the [spec navigation table](spec.md#authentication-and-navigation); successful session establishment ends at `/`, not at the profile. Home-page implementation is outside scope.
- The existing Member Auth page owns the registration/sign-in/verification UI states; no additional verification endpoint or profile policy page is needed. Recheck reloads Firebase identity state and obtains a current ID token; only backend credential checks can approve session establishment. Returning verified users do not see verification. Older auth_time requires fresh sign-in, not another email-verification action. Resend after the initial registration email is explicit, never a side effect of sign-in/page entry.
- member_profiles uses member_id as PK/FK, nullable stored full_name/phone, created_at/updated_at. GET on absent row is read-only. PUT and Member provisioning lock/use the local Member via JPA, controlled DTOs and minimal audit. No policy state is changed.
- Session bootstrap provisions Member atomically under UID uniqueness; duplicate UID race retries outside the failed transaction, never by email. ACTIVE and PENDING_POLICY_ACCEPTANCE are the only allowable bootstrap states; suspension denies.
- Profile eligibility checks backend-verified nonempty email and local status in {ACTIVE, PENDING_POLICY_ACCEPTANCE}; SUSPENDED and other statuses deny. Keep this check distinct from any existing shared entitlement evaluator that requires policy acceptance. Do not weaken those other feature gates, change the enum or update statuses merely to allow 003. Policy reads/availability, consent records and effective versions are not prerequisites for sign-in, session issuance or profile reads/writes.
- API request body has strict exact two-key/type validation, with Bean Validation/custom Unicode name constraint. Web binder has explicit allowed fields and rejects suppressed/duplicate parameters. Reuse the same normalization/service rules.
- API response: fullName/phone/email/emailVerified/updatedAt. Missing local Member returns 409 with code MEMBER_INITIALIZATION_REQUIRED; missing profile is 200 with null profile fields. Shared errors follow existing ErrorResponse schema.
- GET/POST /member/profile; POST /member/profile/logout; GET /member-auth/profile-signin; POST /member-auth/profile-session. Remove the previously proposed dedicated profile-policy GET/POST from this design; do not remove unrelated existing policy routes/code. No endpoint accepts arbitrary returnTo. API routes, request/response schemas and HTTP status sets remain unchanged; 403 descriptions no longer include missing policy acceptance.
- Session/profile/logout mutations have CSRF protection; isolated HTML errors preserve form data without logging it. JSON unknown body is rejected locally, not by changing global Jackson settings.
