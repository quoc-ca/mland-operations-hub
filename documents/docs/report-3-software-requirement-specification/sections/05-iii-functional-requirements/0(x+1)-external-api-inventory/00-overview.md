## (x+1). External API Inventory

|Interface Name|Service / Component|Requirement Description|Details (Based on Context Diagram)|
|---|---|---|---|
|Mail Gateway|Mland-domain SMTP service / Spring Boot `JavaMailSender` (`org.springframework.mail`)|The system must integrate with an external mail service to send automated account-security and workflow emails.|Recipient email, subject, HTML body, OTP or verification token, workshop QR ticket, payment request/receipt, booking-design review result, and order-status notification. The mail gateway only delivers messages and does not make business decisions.|
|Payment Gateway|VNPay payment API, signed IPN, and signed QueryDR recovery|The system must initiate and verify workshop deposits, retail payments, custom-order deposits, and custom-order final-balance payments.|The system validates the signature, transaction reference, amount, success status, and duplicate-event status. The browser Return URL is display-only and never confirms payment. Payment links expire after 10 minutes; the related hold lasts at most 15 minutes.|
|External Registration System|Klook workshop-registration API|The system must exchange approved workshop availability and confirmed-booking information with the external registration partner.|Mland remains the source of truth for branch, session, capacity, and holds. Klook must obtain Mland availability/hold before confirmation. Klook cancellation events are not received or processed in V1.|
|AI API|Gemini API|The system must use an AI service for basic customer text support, booking-design image analysis, and package/product price suggestions.|The system sends only the permitted prompt or consented booking-design image. AI returns text support, image quality, candidate features, or price suggestions. AI never decides custom-manufacturing acceptance, feasibility, or final price. Text logs are retained for at most 30 days and AI image input is not retained after processing.|
|Google Maps API|Google Maps Embed and Google Places|The system must display store locations and permitted public rating/review information through read-only Google services.|The UI must show required Google attribution and a link back to Google Maps. Places review/rating content is not persisted, and the system does not submit reviews to Google.|
|SSO Provider|Google/Facebook SSO using the provider's OAuth/OIDC endpoints|The system must support external identity registration, login, and recovery for Members.|The provider establishes identity and returns identity tokens. Mland resolves account status, business role, and authorization from its own database; provider identity does not grant an application role by itself.|
|Cloud Storage Service|Configured cloud object-storage API|The system must store catalogue media and eligible custom-manufacturing reference images outside the application database.|The system stores only permitted media, applies access control, and deletes or obscures files according to the approved retention rules. Rejected or withdrawn custom requests and independently classified AI images are deleted after processing.|
|Delivery Provider|Giao Hang Tiet Kiem (GHTK); manual handoff only|The system must record Staff-confirmed handoff of a paid retail or custom order to the delivery provider.|V1 does not call GHTK APIs, quote delivery fees, track delivery, process delivery failure, or manage return/cancellation/refund workflows. Recipient and address data are deleted or irreversibly obscured 30 days after handoff.|
