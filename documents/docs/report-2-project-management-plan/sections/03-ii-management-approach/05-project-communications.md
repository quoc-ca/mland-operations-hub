## 5. Project Communications

::: {.docx-table width="100%" columns="18%,20%,30%,14%,18%" repeat-header="false"}

| Communication Item | Who / Target | Purpose | When, Frequency | Type, Tool, Method(s) |
|---|---|---|---|---|
| Daily Update | All members | Report progress and blockers | Daily | Short message in the team chat group |
| Weekly Meeting | All members | Review progress, rebalance tasks, plan the next week | Weekly, evening, about 45 minutes | Online meeting; actions recorded in GitHub Issues |
| Supervisor Meeting | Team and supervisor | Review deliverables and get guidance | Every two weeks and before each report deadline | Online or face-to-face meeting |
| Stakeholder Clarification | Team Leader, feature owners, Mland representative | Confirm business rules and accept iteration demos | At the end of each iteration and when needed | Meeting at the workshop or online |
| Code Review | Change author and one reviewer | Check quality before merging | Every pull request | GitHub pull request |
| Defect / Blocker Report | Affected owner, Team Leader | Make problems visible and assign an owner | As soon as found | GitHub Issue |

:::
