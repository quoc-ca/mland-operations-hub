### 6.2 Source Code Management

The team will use Git and GitHub to review and track product source changes. Each change should have a clear purpose, be developed in a reviewable branch or change set, and receive peer review before it is merged into the agreed integration branch. Work items and defects should link to the related changes, and releases should identify the source revision used.

Automated checks should run before merge and the team should retain their results with the change record. Credentials, private keys, and production data must stay outside the repository. The precise branch-protection rules, release tags, and product-code repository arrangement remain subject to the team's implementation setup; this report does not claim that product runtime code is already present in the documentation repository.
